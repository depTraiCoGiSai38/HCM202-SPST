# 13. IMAGE RESEARCH PROTOCOL

For every candidate image, establish these axes separately.

A. SUBJECT IDENTITY
Who does the original source say is in the image?
Do not infer identity from filename alone.

B. EVENT / DATE
What event/date does the source actually state?
Do not infer event from clothing, appearance, or nearby text.

C. LOCATION
What place does the source actually state?
Do not infer location from event knowledge alone.

D. ORIGINAL SOURCE
Record:
- institution/archive
- item page
- collection/identifier if available
- original URL

Search-result pages are not enough.

E. RIGHTS / USAGE
Record the actual usage information.
Do not convert:
no reuse information found
into:
reuse prohibited
Those are different states.

F. OFFLINE PACKAGING
Confirm the accepted image can be stored locally and included in the offline
build.

# 14. IMAGE STATUS MODEL

Use truthful statuses.

VERIFIED
Only when the image clears all evidence axes required by the project.

PARTIALLY VERIFIED
Use when some axes are established but another remains unresolved.
Example:
- identity confirmed
- original source confirmed
- exact event/date still uncertain

NEED VERIFICATION
Use when provenance is incomplete.

REJECTED
Use when:
- source cannot be traced
- image context conflicts with the intended stage
- usage cannot support inclusion
- the image would mislead the academic narrative

Do not flatten these into one boolean.

# 15. STAGE RELEVANCE OVERRIDES AUTHENTICITY

A photograph may be authentic and still be inappropriate for a stage.

Always distinguish:
Is this image authentic?
from:
Is this image appropriate for THIS stage/event?

Both must pass.

Do not use:
- a 1921 photo for a 1920 event
- a later portrait merely because Hồ Chí Minh appears in it
- a photo from another location to visually represent a specific place

unless the UI explicitly frames it only as a portrait and does not imply
event/date equivalence.

# 17. IMPORT WORKFLOW
