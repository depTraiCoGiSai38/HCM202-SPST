# 51. USER TESTING HONESTY

Do NOT write:

- “students find this more engaging”;
- “users understand better”;
- “lecturers prefer this”;
- “the product improves learning”.

unless actual user evidence exists.

Technical/design observations are allowed.

Example:

`The redesign reduces simultaneously visible navigation systems from X to Y.`

Not:

`Users are less confused.`

# 56. EXECUTION ORDER

Follow this exact sequence:

1. Read governance and current context.
2. Verify the 2019 textbook migration.
3. Inspect current repository and run current product.
4. Invoke and apply `ui-ux-pro-max`.
5. Clone/read reference repo into `_reference/` if possible.
6. Produce `REFERENCE_ANALYSIS.md`.
7. Audit current product.
8. Identify academically supportable spatial nodes.
9. Compare 2D / 3D / hybrid solutions.
10. Write `SPATIAL_JOURNEY_DESIGN_DECISION.md`.
11. Build ONE Stage 2 vertical slice.
12. Run technical/UX/accessibility/offline validation.
13. Refine the spatial model if needed.
14. Expand carefully to the remaining stages.
15. Integrate verified images/documents at meaningful narrative points.
16. Integrate Đối sánh / Nối kết / Tổng hợp into the journey.
17. Run the full test suite.
18. Inspect desktop/tablet/mobile manually.
19. Update Prompt Log and reference-use record.
20. Create `CREATIVE_SPATIAL_JOURNEY_REPORT.md`.

Do not stop at a plan.

Do not stop at a mockup.

Do not stop after building the globe.

The final result must be a working, academically grounded, original creative learning product.

# FINAL DESIGN PRINCIPLE

The learner should remember:

- the place;
- the historical image;
- the moment;
- the transition;
- the development of thought;
- the connection between stages.

They should NOT primarily remember:

- tabs;
- cards;
- menus;
- source badges;
- dashboard controls.
