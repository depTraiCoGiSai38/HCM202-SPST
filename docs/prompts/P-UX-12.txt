# PRODUCT VISION

Redesign “HÀNH TRÌNH TƯ TƯỞNG” into:

# A LIVING DIGITAL HISTORICAL EXHIBITION

The experience should feel closer to:

Digital Museum
× Interactive Documentary
× Editorial Storytelling
× Guided Learning Journey

and NOT:

Dashboard
× Database Browser
× Admin Tool
× Textbook copied into a website

The user should feel that they are moving through a historical and intellectual journey.

---

# PRIMARY EXPERIENCE GOAL

Transform the current experience from:

`ĐỌC THÔNG TIN`

into:

`NHÌN THẤY BỐI CẢNH`
→
`BƯỚC VÀO CÂU CHUYỆN`
→
`KHÁM PHÁ TRẢI NGHIỆM`

→
`KIỂM CHỨNG BẰNG CHỨNG`
→
`SUY NGẪM`

The user should not feel that they are operating a content-management interface.

---

# EXPERIENCE TARGET

The desired feeling:

### First 10 seconds

“Đây là một hành trình, không phải một trang giáo trình.”

### First stage

“Mình hiểu mình đang ở thời kỳ nào và điều gì đang diễn ra.”

### Middle of the journey

“Mình bắt đầu thấy các trải nghiệm và tư tưởng kết nối với nhau.”

### Turning point

“À, đây là lý do giai đoạn này quan trọng.”

### End

“Mình có thể tự giải thích quá trình hình thành và phát triển tư tưởng Hồ Chí Minh.”

Do NOT claim users actually achieved these outcomes until real testing confirms them.

# INTERPRETATION OF “SỐNG TRONG TƯ TƯỞNG HỒ CHÍ MINH”

This phrase does NOT mean:

- character simulation
- roleplay as Hồ Chí Minh
- invented inner monologue

- AI reconstruction of historical events

It means:

The learner is immersed in:

- historical context
- authentic imagery
- chronology
- experiences
- documents
- intellectual transitions
- verified evidence
- reflective questions

The learner should feel present in the historical journey while remaining academically grounded.

# CURRENT UX PROBLEMS TO INVESTIGATE

Based on the current product screenshots, specifically inspect whether:

1. Too many navigation systems compete with each other.

2. Sidebar + tabs + pagination + buttons + timeline create excessive navigation density.

3. The screen feels like an academic dashboard instead of a guided historical journey.

4. Too much text is visible at the same time.

5. Important visual moments do not have enough hierarchy.

6. Photos are treated as secondary blocks rather than narrative anchors.

7. Buttons frequently compete for attention.

8. Internal system states such as:
   - verification
   - source status
   - opened state
   - progress
   appear too prominently in the learning flow.

9. Typography has insufficient hierarchy between:
   - historical moment
   - explanation
   - evidence
   - navigation
   - metadata.

10. Each screen appears structurally different without one strong visual grammar.

---

# ONE COHESIVE DESIGN SYSTEM

The redesign MUST establish one visual grammar across the entire product.

The product should have:

## ONE primary navigation system

The learner should always know:

- where am I?
- which stage am I in?
- what should I do next?

Avoid three or four equally dominant navigation systems.

Secondary controls should move into:

- drawers
- contextual menus
- lightweight utilities

instead of occupying permanent visual space.

---

# PRIMARY NAVIGATION MODEL

Recommended model:

TOP:

`Hành trình tư tưởng`

LEFT / EDGE / MOBILE COLLAPSED:

one continuous five-stage journey indicator

MAIN:

storytelling canvas

RIGHT / DRAWER:

sources and optional supporting information

Avoid keeping:

sidebar navigation
+
large tabs
+
pagination
+
chapter selector
+
multiple CTA rows

all visible simultaneously.

---

# VISUAL HIERARCHY RULE

At any point in the experience there should usually be only:

1 PRIMARY THING TO LOOK AT

1 PRIMARY ACTION

1 OPTIONAL SECONDARY ACTION

Everything else should visually recede.

Do not give metadata the same visual weight as the historical story.

# CENTRAL QUESTION

Preserve the approved Central Question exactly.

Do NOT rewrite it.

Do NOT force the full question to dominate the hero.

Move it into a dedicated section:

# CÂU HỎI DẪN ĐƯỜNG

Present it after the initial emotional introduction.

Use strong editorial typography and generous whitespace.

# FIVE-STAGE VISUAL SYSTEM

IMPORTANT:

## EVERY STAGE MUST HAVE A PRIMARY AUTHENTIC IMAGE OF HỒ CHÍ MINH

This is an intentional product-design decision.

Each of the five stages should have:

### 1 PRIMARY VISUAL ANCHOR

Prefer:

an authentic archival photograph of Hồ Chí Minh appropriate to that period or closely connected to that stage.

### 1–3 SUPPORTING VISUALS

Possible:

- Vietnam historical context
- relevant location
- archival document
- newspaper
- organization/event
- historical environment
- map
- authentic period material

Do not turn the stage into a photo gallery.

Every image needs a narrative role.

---

# IMAGE SELECTION RULE

For each image answer:

`Why is this image here?`

Valid reasons:

- introduces historical context
- establishes time/place
- illustrates a verified event
- connects a person to the stage
- supports a turning point
- helps interpret a document

Invalid reason:

`because the page needs more pictures`

---

# IMAGE SOURCE SAFETY

Use only authentic archival imagery with traceable sources.

Maintain separately:

- identity verification
- event/date verification
- location verification
- image source
- rights/usage condition
- offline packaging status

Do NOT:

- AI-generate Hồ Chí Minh
- generate fake historical photographs
- AI-colorize the portrait
- animate facial expressions
- animate eyes
- lip-sync
- synthesize voice
- face-swap
- morph the face
- make the person perform actions not present in the original source

The regulations prohibit AI-generated/simulated/distorted leader imagery.

Portrait itself must remain authentic and intact.

Every stage should begin with the same orientation grammar.

---

# STAGE STRUCTURE

Every stage should guide the user through:

## 1. ORIENTATION

Where am I?

## 2. CONTEXT

What historical environment am I entering?

## 3. EXPERIENCE

What relevant experiences/events are supported by the source?

## 4. TRANSFORMATION

What changed or developed?

## 5. TURNING POINT

Where applicable.

## 6. EVIDENCE

How can I verify this?

## 7. REFLECTION

What should the learner notice?

## 8. BRIDGE

Why does the next stage follow?

This structure should be felt visually without displaying eight giant menu tabs.

# TURNING POINTS

Major turning points should break the normal rhythm.

Example direction:

## 1920

Before:

visual elements appear fragmented.

As the user reaches the turning point:

timeline lines slowly converge.

Large:

`1920`

appears.

Authentic archival image remains static.

Around the image:

`Trải nghiệm`

→

`Tiếp thu lý luận`

→

`Bước ngoặt`

The image itself must NOT be artificially animated.

Motion happens around the historical material.

---

# MOTION LANGUAGE

Create one coherent motion system.

Motion should communicate:

- progression
- chronology
- reveal
- connection
- transition
- causality

Use:

- subtle fade
- mask reveal
- timeline drawing
- document slide/reveal
- gentle container scale
- small parallax of background layers
- line connection
- chapter transition

Do NOT use:

- bouncing UI
- constant floating elements
- random rotation
- excessive zoom
- scroll hijacking
- animation delays
- looping decoration

---

# PORTRAIT MOTION RULE

Do NOT directly animate the portrait subject.

Allowed:

- image frame reveal
- mask reveal
- entire static image container slightly moves
- gentle crop transition
- background layers move
- caption appears
- timeline draws around the photo
- document overlays enter

The historical photograph remains intact.

---

# DESIGN DENSITY RULES

Actively reduce visual overload.

Use these as design constraints:

- Hero introduction: max 2–3 short lines.
- One primary CTA per major screen.
- Maximum one secondary CTA beside it.
- Do not display all metadata by default.
- Do not display all sources by default.
- Do not show more than one dominant navigation system.
- Body reading width should remain comfortable.
- Avoid very wide text blocks.
- Break long academic material into meaningful sections.
- Use whitespace as part of the narrative.

---

# SOURCE AND VERIFICATION UI

Evidence Visible remains mandatory.

But source infrastructure should NOT visually dominate the learning experience.

Use a lightweight source indicator:

`Nguồn`

or

`Kiểm chứng`

Click:

opens a source drawer.

Drawer contains:

- Claim ID
- source
- section
- page
- volume if relevant
- verification status

If not verified:

`NEED VERIFICATION`

Do not fake completeness.

# REMOVE THE DASHBOARD FEELING

The redesigned product should NOT look like:

- an admin interface
- content management system
- analytics dashboard
- research database

Reduce permanent presence of:

- status badges
- counters
- item counts
- technical labels
- source-state controls
- debugging-like UI

These can exist in contextual drawers.

The central canvas belongs to the learning experience.

# VISUAL STYLE

Direction:

# CONTEMPORARY VIETNAMESE DIGITAL MUSEUM

Use:

- archival photography
- elegant Vietnamese typography
- documentary composition
- warm neutral surfaces
- controlled red accent
- subtle gold / paper accent where appropriate
- editorial grid
- large historical dates
- strong whitespace
- thin journey lines
- authentic document details

Do not turn everything red and yellow.

Avoid:

- SaaS dashboard design
- glassmorphism
- neon
- excessive gradients
- generic Bento cards
- overly rounded components

---

# TYPOGRAPHY

Create a clear hierarchy.

Roles:

DISPLAY
large historical statements / dates

EDITORIAL SERIF
important narrative / quotations where appropriate

SANS UI
navigation / controls / labels

BODY
comfortable long-form reading

SOURCE
small but readable metadata

Do not use six unrelated type styles.

---

# COLOR SYSTEM

Create one restrained system.

Recommended structure:

Base:
warm charcoal / archival dark

Surface:
warm off-white / paper

Primary accent:
muted Vietnamese red

Secondary accent:
subtle archival gold / ochre

Information states:
use separate accessible semantic colors

Do not use accent color for every interactive component.
